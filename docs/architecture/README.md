## 凡例（全図共通）

図をまたいで同じ意味で使います。**この 6 つ以外の形状・色に意味はありません。**

| 表記 | 意味 |
|------|------|
| `A --> B`（実線矢印） | 定常のデータフロー・呼び出し |
| `A -.-> B`（点線矢印） | 通知・テレメトリなどの副次的なフロー |
| 点線枠のサブグラフ | **本番外**（ローカル開発・CI 専用の要素） |
| `{{ラベル}}`（六角形） | **オンデマンド処理**（API / 管理画面から起動。定期バッチではない） |
| `[(ラベル)]`（円柱） | データストア |
| `((ラベル))`（二重円） | 外部 SaaS / 外部 API |

## 更新ルール

- **構成を変えた PR では、該当する図も同じ PR で更新する。** 図が古いまま残ると、コードより先に図を信じて事故る
- **01 を更新したら [`docs/presentations/assets/techtrend-architecture.mmd`](../presentations/assets/techtrend-architecture.mmd) も同期する。** このファイルは 01-A の内容を複製したもので、自動同期はされない
- 図に書いた件数（ソース数・API 数・model 数など）は「◯◯時点」と明記し、取得コマンドを各ファイルの脚注に残す。数値を更新する時はコマンドを再実行してから書き換える
- 事実確認できていない推測を図に載せる場合は、必ず注記で「推測」と分かるようにする

## Mermaid を書く時の制約

GitHub のネイティブ描画で崩れないための取り決めです。

- 使う図種は `flowchart LR/TD`、`sequenceDiagram`、`erDiagram` のみ
- **`%%{init}` ディレクティブは使わない**（Mermaid 10.5 以降で非推奨）。テーマ設定が必要なら frontmatter の `config` を使う
- 1 つの Mermaid ブロックはノード 25 個程度まで。超えるなら図を分割する
- ラベル内の改行は `<br/>`。`{}` `()` `[]` `:` を含むラベルは `"` で囲む
- `erDiagram` の属性は `型 属性名` の順（例: `vector embedding`）
- 色分けは `classDef` で最小限に。ライト / ダークどちらのテーマでも読める淡色のみ使う

### 描画の確認方法

```bash
# ローカルで確認する場合（リポジトリに依存追加はしない）
npx -y @mermaid-js/mermaid-cli -i docs/architecture/01-system-overview.md -o /tmp/out.png
```

ローカルと GitHub では Mermaid のバージョンが異なることがあるため、**最終確認は PR の Files 表示**（ライト / ダーク両方）で行う。
